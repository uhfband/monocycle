# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository shape

`monocycle` (`uhf/monocycle`) is a single-package PHP event-loop library — sockets (TCP, UDP, unix domain), child processes, and timers driven by one `stream_select()` loop. PSR-4 autoload: `Uhf\Monocycle\` -> `src/`. Composer bins: `bin/http_server` (a small HTTP server built on the loop), `bin/db_worker_sqlite` and `bin/db_worker_mysql` (the worker processes behind `Database`, see below). Requires PHP >=7.4, `ext-sockets`, `ext-json`; the SQLite worker also needs `ext-sqlite3`, the MySQL worker `ext-mysqli` (with mysqlnd). Dev deps additionally require `ext-curl` and `ext-mbstring`. Protocol implementations live under `src/Proto/{Http,WebSocket,Mqtt}`.

`README.md` is the user-facing doc and covers timers, processes, sockets (TCP/unix/TLS client/UDP) and files; keep its examples runnable when changing those APIs.

## Dev commands

- Install deps: `composer install`
- Run all tests: `./vendor/bin/phpunit`
- Run unit suite only: `./vendor/bin/phpunit --testsuite unit`
- Run one test method: `./vendor/bin/phpunit tests/unit/HttpServerTest.php --filter testKeepAlive`
- Coverage: `XDEBUG_MODE=coverage ./vendor/bin/phpunit` writes `coverage/html/`, `coverage/clover.xml` and a stdout summary of `src/` (configured in `phpunit.xml`, `coverage/` is gitignored). With Xdebug 2 coverage is always on, so plain runs write the reports too; add `--no-coverage` to skip them.
- Run the bundled HTTP server locally: `HTTP_PORT=8080 WWW_ROOT=tests/unit/fixtures/public ./bin/http_server` (defaults are `HTTP_HOST=0.0.0.0`, `HTTP_PORT=80`, `WWW_ROOT=/var/www/html`, which require root/non-local setup)

There is no linter or build step; `php -l <file>` is the quick syntax check. CI (`.github/workflows/packagist-update.yml`) only notifies Packagist on tag push — it does not run tests.

### Test quirks

- PHPUnit bootstraps via `vendor/autoload.php` (`phpunit.xml`), so deps must be installed first.
- `tests/unit/HttpServerTest.php` runs the HTTP server in-process on an ephemeral port (`tcp://127.0.0.1:0`) and talks to it with a raw `Socket\Connection`, writing request strings and splitting responses by `Content-Length`; `request()` fails on any byte past the response, so over-long bodies are caught (curl would silently truncate them).
- HTTP fixture docroot is `tests/unit/fixtures/public` (used by `HttpServerTest`, `RouterTest` and `PhpCgiTest`); `/` is asserted to return `Hello world!`.
- `tests/TimerMock.php` overrides `time()` inside the `Uhf\Monocycle\Timer` namespace (PHP namespace function fallback trick); `setMockTime($ts)` fixes the clock, `setMockTime(null)` restores it. Load it with `require_once` (a function can only be declared once per process), as `TimerTest` and `ConnectionTimeoutTest` do. Timers are due against `Monocycle::tick()`'s `$now`, which defaults to the real `microtime(true)`, so with a mocked clock run timers only via `$this->tick($timeout, true, $mockedNow)` (see `ConnectionTimeoutTest::advance()`); `pumpUntil(..., true)` would compare mocked deadlines with the real time and fire them all.
- `Monocycle` state is static, so tests reset it in `tearDown()` with `$this->resetMonocycle('sockets', 'timers', ...)` (empties those static registries, killing and closing processes first; `countMonocycle($name)` counts one) and drive the loop instead of `Monocycle::run()` by extending the abstract `tests/BaseTest.php`: `$this->tick($timeout = 1.0, $runTimers = false, $now = null)` runs one iteration, `$this->pumpUntil($condition, $timeoutSeconds = 5.0, $runTimers = false)` ticks until the condition holds and fails the test otherwise (pass `$runTimers = true` when timers or process reaping matter). The helpers are static, so `setUpBeforeClass()`/`tearDownAfterClass()` can use them for per-class fixtures (`SQLiteDatabaseTest` shares one real `bin/db_worker_sqlite` worker this way and drops its tables in `tearDown()`). `DatabaseServerTest` runs `Database\Server` with the SQLite driver in-process on a temp unix socket and talks to it with raw `Protocol` packets. `BaseTest` is loaded via `autoload-dev` classmap in `composer.json`, so run `composer dump-autoload` after a fresh clone if it's not found.
- `tests/unit/PhpCgiTest.php` runs the real `php-cgi` and is skipped when it isn't installed.
- `.gitignore` excludes root-level `/*.php`, so ad-hoc scripts dropped at repo root (e.g. `test_tcp.php`, `test_tls.php`, `test_http_client.php`, used for manual socket/TLS smoke-testing) stay untracked, aren't part of the test suite, and are often out of date with the API.

## Architecture

### The loop is a static registry of stream listeners

`Monocycle` (`src/Monocycle.php`) is the whole runtime: a loop driven by a static `$state` (`RUNNING` -> `SHUTDOWN` -> `HALTED`) plus static arrays. There's no daemon/kernel object and no loop instance to pass around.

What `stream_select()` watches is the **listener registry**: `addReadStream($stream, $cb)` / `addWriteStream($stream, $cb)` (and `removeReadStream`/`removeWriteStream`/`removeStream`), keyed by `(int)$stream`. Each iteration selects on exactly those streams (1s timeout, `IDLE_TIME`) and calls the registered closure; the closure is typically `$this->onReadable()` / `$this->onWritable()` on the owning object, which does its own state-based dispatch. Write interest is toggled on demand: objects add a write listener only when they have buffered data (or are mid-connect) and remove it once drained, otherwise `select()` would spin.

Separately from that, object registries track ownership/lifecycle: `$sockets` (`addSocket`/`removeSocket`, keyed by `Socket::getId()`), `$processes` (by pid), `$timers`. There is no pipe registry: a `Process` owns its `Pipe` objects. `Stream::close()` (and `removeSocket()`) drop the stream's listeners. There is no per-iteration socket sweep: sockets are torn down by their own handlers (`onDisconnect`/`onConnectionError` call `close()`), and timeouts are timers (see Sockets).

Each iteration:
`run()` calls the private `tick($timeout, $runTimers, $now = null)` (tests reach it through `BaseTest::tick()`):
1. `stream_select()` on the registered streams (skipped when none are registered), then dispatch to the read listeners, then the write listeners.
2. With `$runTimers` (set by `run()` once per second, `microtime()`-based): due timers run (`$now` defaults to `microtime(true)`), then every process whose `isRunning()` is false gets `close()`d, which fires `onExit()` with the exit code.

`Monocycle::setFreq()`/`getFreq()` throttle the outer loop (iterations/sec via `usleep`; the default `0` = no throttling), independent of the 1s select timeout and the 1s timer/process tick. `run()` starts an internal 2s stat timer feeding `getStat()`. `stop($graceful, $sendSignal)` stops that timer (so it must only be called after `run()` started) and drops every timer; it closes every registered socket (`$sockets`, so listening servers and connections, each via its own `close()`); with `$sendSignal` it then calls `interrupt()` on each process; then it halts immediately or enters `SHUTDOWN`, where the loop runs until all child processes are gone. Pipes are not closed by `stop()`.

Nothing registers on construction except `Socket\Server`, accepted connections, `UdpSocket`, and `Pipe`: call `Connection::connect()`, `Process::start()`, `Timer::start()`.

### Streams

`Stream\Stream` (`src/Stream/Stream.php`) is the abstract base of `Socket`, `Pipe` and `File\File`. It owns the stream resource in a private `$resource`: the constructor takes an optional one, a subclass that only gets it later (`Connection::connect()`) sets it with the protected `setResource()`, both make it non-blocking (`setNonBlocking()`), subclasses read it via `getResource()`, and `getId()` is `(int)$resource`. It also has a blocking `readSync($length)`, the write buffer (`writeAsync()` appends and throws `StreamException` once the buffer would reach `setWriteBufferSize()` (protected `$writeBufferSize`, default 1MiB); `setReadChunkLength()` defaults to 128KiB; the protected `writeBuffer()` flushes what the stream accepts, removes the write listener and calls `onDrain()` once empty), a blocking `writeSync()` that throws `StreamException`, and `close()` (removes the stream's listeners, `fclose`s it if still open, then calls `onClose()` -> `$onClose($stream)`). `close()` is idempotent via a private `$closed` flag (`isClosed()`; `setResource()` clears it), not `is_resource()`, so a stream that never got a resource (a `Connection` whose `connect()` failed at once) still fires `onClose` once, and repeated closes (a `$onDisconnect` closure calling `close()` before `onDisconnect()`'s own `close(false)`, a pipe whose `onEnd` closes its process) fire it only once. `Socket::close()` returns early on `isClosed()` too, so overrides that add work before `parent::close()` should check it as well. Subclasses set a protected `$closing` flag for a graceful close: `onDrain()` then calls `close()` instead of the `$onDrain` closure. `onData($data)` invokes the `$onData` closure as `($stream, $data)`; `$onDrain` and `$onEnd` get `($stream)`, `$onError` gets `($stream, Throwable $e)`. The base `onEnd()` also removes the read listener. Every `Stream`, `Process` and `Timer` constructor calls `Monocycle::addObject()`, a `WeakReference` list pruned by the stat timer and used only for `getStat()` (leak tracking). It does not keep objects alive.

`File\File` (`src/File/File.php`) takes `fopen()` arguments (throws `StreamException`) and offers `readAsync($length)`: it adds a read listener until that many bytes have been delivered via `onData`, or fires `onEnd` at EOF and stays open. It also has `write()` (buffered, with a write listener while non-empty), `seek()`/`tell()`/`stat()`/`lock()`. Its `close()` is immediate, so close a file you're writing from `onDrain`. Regular files are always select-ready, so each read or write can still block on disk.

### Sockets

`Socket` (`src/Socket/Socket.php`) extends `Stream` and adds a draining `read()` (loops `fread()` until empty, throws `SocketException` on error or on EOF with no data), `accept()`, local/remote address getters, socket options, `close()` (-> `CLOSED`, `removeSocket()`, `fclose`), and a state enum (`STATE_CONNECTING`, `CONNECTED`, `DISCONNECTED`, `CLOSED`, `LISTENING`; no separate TLS-handshake state). Base `setState()` only logs and assigns.

`Socket\Connection` is the single stream-connection class, used both for outbound connections and for accepted ones (there is no separate client/server-client class):
- Outbound: `new Connection()` (or a subclass), set callbacks, then `connect($remoteAddress, $cryptoMethod = null, $sslOptions = null)`. The address/TLS settings are only known after `connect()`; before that `getRemoteHost()`/`getRemotePort()` return `null`. `connect()` does an async `stream_socket_client()`, registers the socket, and adds a write listener to detect connect completion. An immediate failure calls `onConnectionError()`.
- Accepted: `new Connection($stream)` — passing a stream makes the constructor derive `remoteAddress` from the peer name (or `unix://<local path>` for unix sockets, which have no peer name) and register (the `Stream` constructor has already made it non-blocking). `Socket\Server::onReadable()` accepts the socket, instantiates the configured `$connectionClass` this way, calls `onConnection($client)` (closure `$onConnection($server, $client)`), then, if the client wasn't closed in there, `setState(CONNECTED)`, which fires `onConnect()`.
- Lifecycle: `Connection::setState()` dispatches the hooks itself: any transition into `CONNECTED` fires `onConnect`, `CONNECTED -> DISCONNECTED` fires `onDisconnect`, `CONNECTING -> DISCONNECTED` fires `onConnectionError`; the last two then `close(false)`, dropping any buffered writes (a graceful close there would wait forever on a buffer that can't drain while `onWritable()` ignores `DISCONNECTED`, spinning `select()` on the still-registered listeners; the same applies when a timeout fires during a graceful close). So never call `onConnect()` next to `setState(CONNECTED)` (`onWritable()`, `doTlsHandshake()` and `Server::onReadable()` only set the state). `onConnect()` is where the read listener is added, so a subclass overriding it must call `parent::onConnect()`. `close($graceful = true)` waits for the write buffer to drain (like `Pipe`), `close(false)` closes at once; either way it goes straight to `CLOSED`, so a locally closed connection gets no `onDisconnect`.
- Each hook is a method that also invokes the matching public closure property (`$onConnect`, `$onDisconnect`, `$onConnectionError`, `$onDrain`, `$onData`), with the connection as the first argument (`$onData($conn, $data)`, `$onConnectionError($conn, $message)`). Protocol classes override the methods; ad-hoc users (e.g. `Database`) set the closures.
- Writes: `write()` only appends to the `Stream` write buffer (and adds a write listener when connected and the buffer was empty; `onConnect()` adds it for data written while connecting); `onWritable()` flushes via `writeBuffer()`, `onDrain()` fires when empty. A read `SocketException` or write `StreamException` moves the connection to `DISCONNECTED`. A read that yields `''` without EOF (e.g. a TLS-internal record) is ignored.
- A failed async connect shows up as writable with no peer name and becomes `DISCONNECTED` with `Connection refused`.
- Timeouts: chainable `setConnectTimeout($s)`, `setReadTimeout($s)`, `setWriteTimeout($s)`. None is set by default, so a connection without `setConnectTimeout()` never times out while connecting. Each setter creates a one-shot `Timer` (`$connectTimeoutTimer`/`$readTimeoutTimer`/`$writeTimeoutTimer`, via the private `setTimeoutTimer()`) that sets `DISCONNECTED` with `Connect timeout`/`Read timeout`/`Write timeout`; calling it again changes the delay (moving a running timer's deadline to now + delay), `0` stops and drops the timer, and a setter called while its phase is already under way (connecting with a socket, connected, connected with buffered data) starts the timer itself. `connect()` starts the connect timer; `onConnect()` stops and drops it, then starts the read timer (and the write timer if data was written while connecting). `onData()` `reset()`s the read timer, so only inbound data keeps a connection alive (a connection that only sends still times out). The write timer runs only while data is buffered: started (if not already running) by `write()` into an empty buffer, `reset()` after each flush in `onWritable()` and stopped in `onDrain()`. All three are stopped and dropped in `onClose()` (which then calls `parent::onClose()`, so `$onClose` fires), i.e. only when the stream really closes, so they keep running during a graceful close that waits on the write buffer. Timers are second-granularity, so a timeout can fire up to ~1s late or early.
- TLS is client side only (no TLS server): a writable `CONNECTING` connection with a crypto method runs `doTlsHandshake()` step by step until it succeeds or fails.

`Socket\Server` binds, listens and registers in its constructor (there is no `listen()`; a bind failure throws `SocketException` from `new`), unlinking a stale unix socket file at its path first. Subclasses that set fields after `parent::__construct()` are fine, since nothing is dispatched until the loop ticks. Chainable `setMaxConnections($n)` (default `0` = unlimited) caps open accepted connections: the server tracks them as `WeakReference`s and counts the ones still open (`getConnectionCount()`, so one closing gracefully counts until it really closes); over the limit the raw accepted stream is `fclose()`d without creating a connection object, with only a warning log (no hook). `Socket::accept()` throws `SocketException` on failure; `Server::onReadable()` logs it and skips that accept. `Socket\UdpSocket` binds and registers in its constructor (default `udp://0.0.0.0:0`) and dispatches to `onRecvFrom($data, $from)` (closure `$onRecvFrom($socket, $data, $from)`); receive/send with `recvFrom()`/`sendTo()`; a read error logs a warning and closes it. `parse_url()` rejects both `unix:///path` and a literal port `0`, so those schemes are detected with `strncmp()`, not `parse_url()`.

### Protocols

- `Proto/Http/Server/Server` extends `Socket\Server` and owns a `Router`, handing it to each accepted `Proto/Http/Server/ServerClient` (a `Connection`) in `onConnection()`. `Router::route()` checks callback routes (`addRoute()`), then serves files from `$wwwRoot` (index resolution, `..` stripped, Range/206), dispatching `.php` to `PhpCgi`. Requests/Responses use `symfony/http-foundation`. `PhpCgi` runs `php-cgi` as an async `Process`; the response is delivered via callback on stdout EOF (502 for output without a CGI header block, 504 + `kill()` on timeout, default 30s).
- `Proto/Http/Client/Client` extends `Connection` for a single request: constructor takes URL, method, options (`headers`, `query`, `body`, `json`, `form_params`, `auth`, `verify`, `timeout`, a whole-request deadline started by `connect()` that fails the request) and derives the address/TLS settings; its `connect()` takes the parent's arguments as optional overrides, so plain `connect()` works. Set `onHttpResponse($client, $response)`/`onError($client, $e)` closures. Digest `auth` answers the 401 challenge with a fresh `Client` reporting through the original's callbacks.
- `Proto/WebSocket/Server/{Server,ServerClient}` extend the HTTP server classes (handshake rides on an HTTP upgrade) and add `addMessageHandler()` plus frame parsing (`Parser`).
- `Proto/Mqtt/Client` extends `Connection` directly and implements MQTT framing; like the HTTP client it derives the address from a URL in its constructor, calls `$onMessage($client, $topic, $payload)`, and overrides `connect()` with optional arguments. After CONNACK a keep-alive `Timer` sends PINGREQ every `keepAlive - 2` seconds unconditionally (sending other packets does not postpone it), and the constructor's `$timeout` is the read timeout (default `keepAlive + 10`, set next to a 10s connect timeout): the PINGRESPs are what keeps a publish-only client's read timeout from firing, so don't make pings conditional on outbound activity.

Where a protocol class shares a short name with the socket-layer class it extends, it imports it with an alias (`Server as SocketServer` in the HTTP server, `Connection as BaseSocketClient` in MQTT, `Server as HttpServer`/`ServerClient as HttpServerClient` in WebSocket); they inherit the connection lifecycle rather than reimplementing it.

### Processes and pipes

`Process::start()` calls `proc_open()`, wraps each `pipe` descriptor in a `Pipe\Pipe` (`src/Pipe/Pipe.php`), then registers itself with `addProcess()`. `Pipe` extends `Stream` (so it is non-blocking from construction); pipe modes are named from the descriptorspec (child's view): a `'w'` descriptor becomes `Pipe::MODE_WRITE` and is the one the parent **reads** (a read listener is added for it). Reads fire the pipe's `$onData($pipe, $data)` closure, which `Process::start()` points at `Process::onStdout($data)`, `onStderr($data)`, or for any other pipe `onData($data, $pipeNum)` (the process's `$onStdout`/`$onStderr` closures get `($process, $data)`, `$onData` gets `($process, $data, $pipeNum)` and `$onExit` gets `($process, $code)`). `Process` keeps the `Pipe` objects in its own `$pipes` (by pipe number) and sets each pipe's `$onClose` to drop it from there, so `getPipe()` returns `null` once a pipe is closed; don't replace a pipe's `$onClose`. Writing to a child is buffered (`Process::write()` -> `Pipe::write()`), flushed when writable. `Pipe::close()` is graceful by default: with data still buffered it only marks the pipe closing and finishes the close once the buffer drains (so `Process::closePipe()` right after `write()` is safe); `close(false)` closes at once. When the other end closes the pipe normally (readable, `read()` returns `''`, `isEof()` is true), only a debug log is written, `$onEnd($pipe)` fires and the pipe is closed; a read/write error logs a warning, fires `$onError($pipe, $e)` (a `ProcessException` from a read, a `StreamException` from a write) and closes it. Either way the callback runs before the close (so `Process::getPipe()` still returns the pipe inside it), and the close is immediate (`close(false)`, buffered data is dropped). When that callback closes the process (the default handlers below), `Process::close()` already closes the pipe, and the pipe's own `close(false)` that follows is a no-op. `read()` returns `''` instead of throwing when there's nothing to read, and throws `ProcessException` only for real errors. A pipe closing does not by itself reap the child (`Process::start()` sets each pipe's `$onEnd` and `$onError` to close the process if it has exited, but `PhpCgi` replaces both on stdout, and the DB workers set both on their stdin to exit when the parent is gone), otherwise an exited child is noticed on the per-second tick (so a consumer like `PhpCgi` reacts to stdout EOF rather than `onExit`). `Process::close()` closes the remaining pipes with `close(false)`, calls `proc_close()`, and fires `onExit()` once with the exit code recorded by `isRunning()` (`128 + signal` for a signal-killed child), falling back to `proc_close()`'s result; call it only once, since it throws on an already closed process.

### Database: async queries via a worker process

`Database\Database` is an abstract client; each engine subclass has a static `open()` that spawns its worker via `Database::spawn()` (a `Process` listening on a temp unix socket). `Database\SQLite\Connection::open($dbPath, $initScript, $timeout)` runs `bin/db_worker_sqlite`; `Database\MySQL\Connection::open($dbName, $connection, $initScript, $timeout)` runs `bin/db_worker_mysql`, passing credentials via the worker's environment (`MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_SOCKET`, `MYSQL_USER`, `MYSQL_PWD`) so they don't show in `ps`. A missing database/file is created and the init script runs only then (MySQL drops it again if the script fails). The MySQL worker pings every 60s (`MySQL\Driver::ping()`) to stay under `wait_timeout`; a lost connection fails the request that hit it and is reopened on the next one, without retry (session state is gone).

Workers are themselves Monocycle apps: a `Database\Server` (a `Socket\Server` on `unix://...` that decodes requests and hands them to a `Database\Driver`: `Database\SQLite\Driver` or `Database\MySQL\Driver`, which open/create the database in their constructor and throw `DatabaseException`). Its client connections get a write buffer of `Server::WRITE_BUFFER_SIZE` (four maximum-size packets, set before `$onConnection`); a response over `Protocol::MAX_PACKET_SIZE` (16MiB, which the client would reject as a protocol error and drop the connection) or one that doesn't fit in the buffer is replaced by an error response for that query only, and a client is dropped only if not even that fits. `Database\Server::onClose()` closes the driver and removes the socket file, which happens when `Monocycle::stop()` closes all sockets. The MySQL worker's keep-alive timer calls `MySQL\Driver::ping()`. The client connects with a `Socket\Connection`, retrying on a 1s interval timer until the socket file appears. Wire format (`Database/Protocol.php`): 4-byte big-endian length + JSON, matched by `query_id`. `query($sql, $callback, $timeout)` never blocks; callback is `function (?array $rows, ?string $error, int $returnCode)` with `RETURN_CODE_*` (success, error, database closed, timeout). Queries already sent when the connection drops fail (they may or may not have executed); unsent ones wait for reconnect. `Database` chains onto the worker `Process::$onExit` so a dying worker closes the database and fails pending queries.

### Timers

`Timer\Timer` is one class configured with chainable setters: `setDelay($s)` (one-shot), `setInterval($s)`, `setTimestamp()`/`setDateTime()` (one-shot at a time), `setCronExpression()` (via `dragonmantank/cron-expression`); then `start()` (throws `Timer\TimerException` if already running or unconfigured; there is no shared exception namespace, each exception lives next to its component: `Process\ProcessException`, `Socket\SocketException`, `Stream\StreamException`, `Timer\TimerException`, `Database\DatabaseException`, `Database\ProtocolException`, `Proto\Http\Client\RequestException`). `start()` and `reset()` re-base delay/interval deadlines on the current `time()` (`reset()` works on a stopped timer too and leaves timestamp/cron deadlines alone). After the callback (which receives the timer), `run()` reschedules: cron asks the expression, interval does `nextRun += interval` (catches up after a stall, one firing per tick, rather than skipping), anything else `stop()`s. A `TimerException` from a callback is logged and the timer deleted; other exceptions propagate out of `Monocycle::run()`. All scheduling is second-granularity.

### Event handler visibility

Every `on*` event-handler method (`onConnect`, `onData`, `onConnection`, `onExit`, ...) is `protected`: subclasses override them, user code sets the public closure properties of the same name instead. The loop and other classes never call an `on*` method directly; they go through a public entry point (`Process::close()`, a `Pipe`'s `$onData` closure, the stream listener closures). Keep new handlers protected, and remember PHP forbids narrowing visibility in a subclass, so an override can't be stricter than its parent.

### Logging and slow-call profiling

`Monocycle::getLogger()` lazily builds a Monolog logger writing colorized lines to stdout; level is `Monocycle::setLogLevel()`/`getLogLevel()` (default `Logger::WARNING`, a Monolog level constant; setting it also updates the default logger if already built); `setLogger()` replaces it (that logger keeps its own levels) (workers log to STDERR because their stdout is a pipe the parent doesn't read). Slow-call detection: `$profiler = Monocycle::startProfiler();` before a call, `$profiler->stop($what, $context)` in a `finally`; calls longer than `setMaxCallDuration()` (default 0.1s, `0` disables) log a `Slow call:` warning. Wrapped today: `UdpSocket::onReadable()`, `Timer::run()`, and `Connection::doTlsHandshake()`. TCP read/accept/write, pipe I/O, and process callbacks are not profiled — wrap new dispatch the same way. It's a single-threaded loop, so one slow callback blocks everything.
